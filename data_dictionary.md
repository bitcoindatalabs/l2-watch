# Liquid Audit Data Dictionary

This document outlines the schema and purpose of every raw JSONL file extracted to the `D:\LiquidAudit\data` directory by the Liquid Elements extractor.

## 1. Core Transaction Data

### `transactions.jsonl`
Contains all transactions extracted from the Liquid blockchain.
- **`block_height`** (int): The block height containing the transaction.
- **`block_hash`** (str): The hash of the block.
- **`block_time`** (int): Unix timestamp of the block.
- **`txid`** (str): The transaction ID on the Liquid network.
- **`fee`** (float): Total transaction fee paid in L-BTC.
- **`size`** / **`vsize`** (int): The physical and virtual size of the transaction.
- **`is_pegin`** (bool): True if the transaction mints L-BTC from the mainchain.
- **`is_pegout`** (bool): True if the transaction burns L-BTC to unlock mainchain BTC.
- **`is_issuance`** (bool): True if the transaction issues a new asset.
- **`has_blinded_outputs`** (bool): True if the transaction uses Confidential Transactions (CT).
- **`tracked_assets`** (list[str]): List of asset IDs involved if they match the registry (e.g., BMN, USDt).
- **`inputs`** (list[dict]): The inputs consumed by the transaction.
- **`outputs`** (list[dict]): The outputs created by the transaction.

### `pegins.jsonl`
A filtered subset of `transactions.jsonl` containing only peg-in transactions.
- *Schema is identical to `transactions.jsonl`*. 
- **Key Input Fields**:
  - `pegin_txid` (str): The Bitcoin mainchain transaction ID that locked the BTC.
  - `pegin_claimed_btc` (float): The amount of L-BTC minted.
  - `pegin_claim_script` (str): The script used for the mainchain claim.
  - `pegin_genesis_hash` (str): The genesis hash for chain verification.

### `pegouts.jsonl`
A filtered subset of `transactions.jsonl` containing only peg-out transactions.
- *Schema is identical to `transactions.jsonl`*.
- **Key Output Fields**:
  - `pegout_address` (str): The destination Bitcoin address on the mainchain.
  - `pegout_value` (float): The amount of L-BTC burned (unblinded).

## 2. Mainchain Verification Data

### `pegin_verifications.jsonl`
Generated by `verify_pegins.py`. Contains the independent mainchain verification status of every peg-in.
- **`pegin_txid`** (str): The mainchain locking transaction.
- **`liquid_txid`** (str): The Liquid claiming transaction.
- **`pegin_claimed_btc`** (float): The amount claimed on Liquid.
- **`meets_102_threshold`** (bool): True if the mainchain TX has >= 102 confirmations.
- **`peg_address_found`** (bool): True if the BTC was sent to a known federation address.
- **`peg_output_value_btc`** (float): The actual amount received by the federation address.
- **`amount_matches`** (bool): True if `pegin_claimed_btc` == `peg_output_value_btc`.
- **`is_double_spend`** (bool): True if the `pegin_txid` was used to mint L-BTC more than once.
- **`full_audit_pass`** (bool): True ONLY if all the above checks pass.

### `pegout_verifications.jsonl`
Generated by `verify_pegouts.py`. Contains the independent mainchain verification status of every peg-out.
- **`liquid_txid`** (str): The Liquid burning transaction.
- **`pegout_address`** (str): The intended destination Bitcoin address.
- **`mainchain_txid`** (str): The Bitcoin transaction that released the funds.
- **`mainchain_output_value_btc`** (float): The actual BTC received on the mainchain.
- **`address_found`** (bool): True if the `pegout_address` received funds.
- **`amount_matches`** (bool): True if the burned L-BTC matches the received BTC.

### `double_spend_alerts.jsonl`
Generated automatically if a mainchain UTXO is used in multiple Liquid peg-ins.
- **`pegin_txid`** (str): The offending mainchain transaction.
- **`liquid_txids`** (list[str]): The multiple Liquid transactions that claimed it.

## 3. Network Health & Federation Audits

### `block_headers.jsonl`
Contains aggregate block statistics and DynaFed epoch data.
- **`height`**, **`hash`**, **`time`** (int/str): Block identifiers.
- **`block_interval_seconds`** (int): Time since the previous block.
- **`block_total_vsize`** (int): Total virtual size of all transactions.
- **`block_total_fees_lbtc`** (float): Total fees collected in the block.
- **`signblock_witness_path`** (str): "normal", "emergency", or "low_threshold" signing path.
- **`signblock_sig_count`** (int): Number of functionary signatures (usually 11 of 15).
- **`dynafed_signblockscript`** (str): The active script used to sign blocks.

### `federation_transitions.jsonl`
Logs any changes to the federation's consensus rules or multi-sig addresses.
- **`change_type`** (str): "fedpegscript" (peg address change) or "signblockscript" (functionary change).
- **`new_fedpegscript`** (str): The new script used for locking Bitcoin.
- **`bitcoin_mainchain_address`** (str): The decoded Bitcoin multi-sig address for peg-ins.
- **`functionary_pubkeys`** (list[str]): The 15 extracted public keys of the block signers.

### `block_signing_anomalies.jsonl`
Logs any blocks that deviate from normal federation behavior.
- **`anomaly_types`** (list[str]): e.g., `["gap_204s"]` or `["emergency_path"]`.
- **`signing_path`** (str): "normal", "emergency", or "low_threshold".
- **`sig_count`** (int): Number of signatures found (flags if < 11).
- **`signblock_witness_raw`** (list[str]): The raw hex signatures (Warning: Causes file bloat on minor gaps).

### `coinbase_txs.jsonl`
Extracts the fee recipient (first transaction) of every block to audit where fees are going.
- **`coinbase_txid`** (str): The transaction ID.
- **`outputs`** (list[dict]): The outputs receiving the block fees, including `address` and `value`.

## 4. True Supply & Asset Metadata

### `l_btc_supply_history.jsonl` / `utxo_snapshots.jsonl`
*(Note: Currently affected by the `coinstatsindex` bug and requires a fresh run).*
- **`snapshot_height`** (int): The block height at the time of snapshot.
- **`l_btc_total`** (float): The definitive, native L-BTC total supply according to the UTXO set.
- **`utxo_count`** (int): Total number of unspent outputs on the network.

### `asset_registry_cache.json`
A static mapping of asset hashes to human-readable tickers (built by `bootstrap_registry.py`).
- **`asset_id`** (str): The 64-character asset hash.
- **`ticker`** (str): The short ticker (e.g., "USDt", "BMN1").
- **`name`** (str): The full name of the asset.

### `proofs.jsonl`
Merkle proofs generated for critical transactions (peg-ins, peg-outs, issuances) before the node prunes the raw block data. Used for cryptographically proving a transaction existed without needing a 2TB full node.
